# dnsgate_url_forward (Resource)

The URL forward (HTTP redirect) of a name in a zone served by a dns-gate: the DNS provider answers HTTP requests for the name with a 301 or 302 redirect to `url`, or with a page showing it in a frame. Only zones whose DNS provider has URL forwards (EuroDNS) have them. Like a record set, the forward is owned by a team of the provider identity in the gate (its default team, or `team`), and every change is audited. Creation fails if the name already has a forward: adopt it in the gate, then import it.

## Example Usage

```terraform
# go.example.com answers HTTP requests with a permanent redirect.
resource "dnsgate_url_forward" "go" {
  zone = "example.com"
  name = "go"
  type = "301"
  url  = "https://www.example.com/landing"
}

# The apex shows the shop in a frame, the browser keeping example.com in its
# address bar. title, keywords and description are for frame forwards only.
resource "dnsgate_url_forward" "apex" {
  zone        = "example.com"
  name        = "@"
  type        = "frame"
  url         = "https://shop.example.net/"
  title       = "Example shop"
  keywords    = "shop, example"
  description = "The example shop"
}

# Fail the apply rather than create a forward that answers plain HTTP only:
# the domain must have an HTTPS redirect subscription at the DNS provider.
resource "dnsgate_url_forward" "promo" {
  zone          = "example.com"
  name          = "promo"
  type          = "302"
  url           = "https://www.example.com/promo"
  require_https = true
  team          = "web"
}
```

## Schema

### Required

- `name` (String) Name relative to the zone, lowercase, without trailing dot: `go`, `www`, `@` for the apex. Changing it replaces the forward.
- `type` (String) `301` (permanent redirect), `302` (temporary redirect) or `frame` (a page showing `url` in a frame, the browser keeping the forwarded name in its address bar).
- `url` (String) Target, an absolute `http://` or `https://` URL of at most 2048 bytes in canonical form, without user name, password, spaces nor unencoded `<>"'`\{}|^`, for example `https://www.example.com/landing`.
- `zone` (String) Zone name, lowercase without trailing dot, for example `example.com`. Changing it replaces the forward.

### Optional

- `description` (String) Meta description of the frame page, plain text of at most 1000 characters without `<`, `>`, `"`, `'` nor `` ` ``. Only with `type = "frame"`.
- `keywords` (String) Meta keywords of the frame page, plain text of at most 500 characters without `<`, `>`, `"`, `'` nor `` ` ``. Only with `type = "frame"`.
- `require_https` (Boolean) Fail the apply instead of writing a forward that answers plain HTTP only: the gate refuses the write (`409 https_unavailable`) unless the forwards of the zone answer HTTPS (`https_status` `active`, `no_forward`; `pending` is refused, its certificate is not issued yet). Sent on every write, never read back: the state keeps the configured value. Default `false`.
- `team` (String) Team of the provider identity to act for, when it belongs to several teams in the gate. Sent as the `X-DNS-Gate-Team` header on create, update and delete: the forward is created for this team, and the gate refuses to change it unless this team owns it. Unset, the gate uses the default team of the identity. Changing `team` never moves an existing forward to another team: the plan fails unless the forward is already owned by the new team (same rules as `dnsgate_record_set`).
- `title` (String) Title of the frame page, plain text of at most 200 characters without `<`, `>`, `"`, `'` nor `` ` ``. Only with `type = "frame"`.

### Read-Only

- `https_status` (String) Whether the forwards of the zone answer HTTPS requests, as the gate reads it from the DNS provider: `active`, `no_forward` or `pending` (an HTTPS redirect subscription covers the domain, `pending` while its certificate is issued), `inactive` (plain HTTP only), `unsupported` (the provider has no forwards), `unknown`.
- `id` (String) `<zone>/<name>`, also the import id.
- `owner_team` (String) Team that owns the forward in the gate.
- `status` (String) Ownership status in the gate: `managed`, `pending`, `tainted` (modified outside the gate, writes blocked until reviewed), `foreign` (not owned by the gate).

## Availability and permissions

URL forwards exist only on zones whose DNS provider has them: EuroDNS. On a zone of another provider (Route53),
the gate refuses the forward with `400 invalid`. The provider needs a gate that advertises the `forwards` feature
(`GET /.well-known/dns-gate`); older gates fail at plan time with an explicit error.

In the gate, a forward is the RRset of type `URLFWD` of its name: it appears with that type in the zone inventory
(`dnsgate_record_sets`), and adoption and transfers handle it like any RRset. Writing it takes the action
`dns.forward.write` on the zone, scoped by the `records.hosts` patterns of the role like record writes
(`records.types` does not apply).

## HTTPS

A forward redirects the requests that reach the forwarded name. Whether it also answers `https://` requests depends
on the DNS provider, not on the target: at EuroDNS, the forwards of a domain answer HTTPS only when the domain has an
HTTPS redirect subscription, a paid product ordered at EuroDNS, outside the gate (the gate never orders one).
Without it, a forward answers plain HTTP only. `url` may be an `https://` URL either way.

`https_status` shows what the gate reads from the provider for the zone: `active`, `no_forward` or `pending` (certificate
being issued) when a subscription covers the domain, `inactive` when the forwards answer plain HTTP only, `unsupported` for a provider without
forwards, `unknown` when the gate cannot tell.

With `require_https = true`, the gate refuses the write (`409 https_unavailable`) unless the forwards of the zone
answer HTTPS (`active`, or `no_forward` for the first forward of a subscribed domain; `pending` is refused, its
certificate is not issued yet, and so is a subscription past its expiration date): the apply fails instead of creating or changing a forward that would answer plain HTTP only.
`require_https` is sent on every write and never read back; changing it alone writes the forward again, unchanged,
so that the gate checks HTTPS.

## Ownership and teams

The forward is owned by a team in the gate (`owner_team`), with the same rules as `dnsgate_record_set`: writes from
other teams are refused (`403 not_owner`), as are writes on a forward created outside the gate (`409 foreign_rrset`)
or modified outside the gate (`409 tainted`). `team` selects the team the identity acts for (`X-DNS-Gate-Team`), and
changing it never moves the forward to another team: request a transfer in the gate (type `URLFWD`), then set
`team` to the new owner.

Each write is conditional: create sends `If-None-Match: *`, update and delete send `If-Match` with the content hash
of the forward as last read, so a change made in the gate since the last refresh fails with `412` instead of being
overwritten. A forward deleted outside Terraform is removed from the state and created again by the next apply.

## Import

In Terraform 1.5 and later, use an `import` block with the id `<zone>/<name>`:

```terraform
# Terraform or OpenTofu >= 1.5.
import {
  to = dnsgate_url_forward.go
  id = "example.com/go"
}
```

or the command:

```shell
# <zone>/<name>, name relative to the zone, @ for the apex. The forward must
# be owned by the team of the provider identity in the gate: adopt foreign
# forwards in the gate first.
terraform import dnsgate_url_forward.go example.com/go
terraform import dnsgate_url_forward.apex example.com/@
```

Only forwards owned by a team of the provider identity can be imported. A forward created outside the gate is
*foreign*: adopt it for the team in the gate first (web UI, or `POST /api/v1/zones/{zone}/adopt` with the host and
type `URLFWD`). An imported forward has `require_https = false` and no `team` in the state: when the configuration
sets them, the first plan shows an update.
