# dnsgate_record_set (Resource)

All records of one name and type (an RRset) in a zone served by a dns-gate, whatever the DNS provider behind it. The RRset is owned by the team of the provider identity in the gate: the gate refuses changes from other teams and records every change in its audit trail. Creation fails if the RRset already exists: adopt it in the gate, then import it.

## Example Usage

```terraform
resource "dnsgate_record_set" "www" {
  zone   = "example.com"
  name   = "www"
  type   = "A"
  ttl    = 300
  values = ["192.0.2.10", "192.0.2.11"]
}

# Target names may be written with or without trailing dot.
resource "dnsgate_record_set" "blog" {
  zone   = "example.com"
  name   = "blog"
  type   = "CNAME"
  ttl    = 3600
  values = ["example.github.io."]
}

resource "dnsgate_record_set" "mx" {
  zone   = "example.com"
  name   = "@"
  type   = "MX"
  ttl    = 3600
  values = ["10 mx1.example.net.", "20 mx2.example.net."]
}

# TXT values are written unquoted, at any length: the gate splits them in
# 255-byte strings for the DNS provider, and the provider compares the
# concatenated text, so a DKIM key never shows a perpetual diff.
resource "dnsgate_record_set" "dkim" {
  zone   = "example.com"
  name   = "selector1._domainkey"
  type   = "TXT"
  ttl    = 3600
  values = ["v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAx3ylhXuPNbGQvJxZ0sO4QbmX0N1F7y5Ul6UqGmpTzXz4rXfiwR3Npx6lfsY3gbDpzaD8F1yH0X1H1o8xG5Wkzv7QZx9Vq1e3rT3c8D2yQyNnQ2vDgJmB6V8bTzQ4m8yq0XhWf6j1nO7mI2rQGqS2lQe0uW7nHkR5t2cP0yVwF9eL3bJz8aKpQ4sR1mN6vT0xYiUoE3wZ2gH7jK9lF5dC8bA1nM4qW6eR0tY2uI9oP3aS5dF7gH1jK3lZ6xC8vB0nM2qW4eR6tY8uI0oP2aS4dF6gH8jK0lZ2xC4vB6nM8qW0eR2tY4uI6oP8aS0dF2gH4jK6lZ8xC0vB2nM4qWIDAQAB"]
}

# Alias to a CloudFront distribution (Route53 zones): no ttl, no values.
resource "dnsgate_record_set" "apex" {
  zone = "example.com"
  name = "@"
  type = "A"

  alias {
    name                   = "d111111abcdef8.cloudfront.net"
    zone_id                = "Z2FDTNDATAQYW2" # CloudFront
    evaluate_target_health = false
  }
}
```

## Schema

### Required

- `name` (String) Name relative to the zone, lowercase, without trailing dot: `www`, `_dmarc`, `*.apps`, `@` for the apex. Changing it replaces the record set.
- `type` (String) Record type, uppercase: `A`, `AAAA`, `CNAME`, `MX`, `TXT`, `CAA`, `SRV`, `NS`... The types accepted depend on the DNS provider of the zone; SOA is never managed. Changing it replaces the record set.
- `zone` (String) Zone name, lowercase without trailing dot, for example `example.com`. Changing it replaces the record set.

### Optional

- `alias` (Block, Optional) Alias target (Route53 alias records, for example to a CloudFront distribution or a load balancer), instead of `values` and `ttl`. Only for zones whose DNS provider supports aliases. (see [below for nested schema](#nestedblock--alias))
- `ttl` (Number) TTL in seconds. Required with `values`, not allowed with `alias` (the TTL of an alias is the target's). Some DNS providers accept only a closed list of TTLs (EuroDNS).
- `values` (Set of String) Record data, one entry per record, in zone file presentation format: `192.0.2.1`, `10 mx.example.net.`, `v=spf1 -all`. Exactly one of `values` and `alias`. Values are compared by meaning, not by text (see *Value comparison*): target names with or without trailing dot and in any case, TXT values quoted or not, split in 255-byte strings or not, are the same records.

### Read-Only

- `id` (String) `<zone>/<name>/<type>`, also the import id.
- `owner` (String) Team that owns the RRset in the gate.
- `status` (String) Ownership status in the gate: `managed`, `pending`, `tainted` (modified outside the gate, writes blocked until reviewed), `foreign` (not owned by the gate).

## Value comparison

The gate, or the DNS provider behind it, may store a value in another form than the configuration: Route53
returns names with a trailing dot and TXT values quoted and split in 255-byte strings, EuroDNS keeps them as
sent. To avoid perpetual diffs, the provider compares values by meaning, using the zone file parser of
[miekg/dns](https://github.com/miekg/dns) (the gate's Route53 adapter canonicalizes values with the same
library). Each value is parsed as the record `x.invalid. 300 IN <type> <value>` with `.` as origin, then:

| Record data | Compared as |
|---|---|
| Domain names inside the value (CNAME, NS, PTR targets, MX exchange, SRV target, SVCB/HTTPS target...) | absolute names, case-insensitive: `Target.Example.net` = `target.example.net.` |
| TXT, SPF | the concatenation of the character-strings: quotes and chunking are ignored, escapes decoded. An unquoted value is one string, as with the AWS provider, so `a""b` reads as the strings `a` and `b` |
| IP addresses, numbers, CAA, other fields | parsed values: `2001:DB8::1` = `2001:db8:0:0:0:0:0:1`, `0 issue letsencrypt.org` = `0 issue "letsencrypt.org"` |
| A value that does not parse, or a type the parser does not know | the exact string |
| Alias `name` | case-insensitive, trailing dot optional; `zone_id` case-insensitive |

The comparison is deliberately conservative: TTLs, the number of values, letter case of TXT data and every
field other than domain names are compared exactly. When the configuration and the gate hold the same
records, the plan keeps the stored form and shows no change, including right after an import. A value the
parser does not understand produces a plan-time warning: it is then compared as an exact string, so write it
in the form the gate stores (the `dnsgate_record_sets` data source or the gate's Terraform export show it).

Names inside values are absolute whether or not they end with a dot. Through a gate, a CNAME target written
`target.example.net` means `target.example.net.`, never `target.example.net.<zone>`.

## Ownership

The RRset is owned by the team of the provider identity in the gate (`owner`). The gate refuses writes from
other teams (`403 not_owner`), on RRsets created outside the gate (`409 foreign_rrset`) and on RRsets modified
outside the gate (`409 tainted`, `status = "tainted"`) until an administrator reviews them. A plan shows a
warning for tainted or foreign RRsets.

## Import

In Terraform 1.5 and later, use an `import` block with the id `<zone>/<name>/<type>`:

```terraform
# Terraform or OpenTofu >= 1.5. GET /api/v1/zones/{zone}/terraform?team=<team>
# on the gate generates these blocks for every RRset of the team.
import {
  to = dnsgate_record_set.www
  id = "example.com/www/A"
}
```

or the command:

```shell
# <zone>/<name>/<type>, name relative to the zone, @ for the apex. The RRset
# must be owned by the team of the provider identity in the gate: adopt
# foreign RRsets in the gate first.
terraform import dnsgate_record_set.www example.com/www/A
terraform import dnsgate_record_set.apex example.com/@/A
```

Only RRsets owned by the team of the provider identity can be imported. An RRset created outside the gate is
*foreign*: adopt it for the team in the gate first (web UI, or `POST /api/v1/zones/{zone}/adopt`). The gate
generates the configuration and the import blocks of a team's RRsets with
`GET /api/v1/zones/{zone}/terraform?team=<team>`.
