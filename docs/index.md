# dnsgate Provider

Manages DNS record sets through a [dns-gate](https://github.com/KamorionLabs/dns-gate), a security
gateway in front of DNS provider APIs (EuroDNS, Route53...). The gate holds the provider credentials;
Terraform only presents a short-lived identity (AWS, Entra ID, Azure DevOps, GitHub Actions OIDC...) and the
gate enforces, on every request:

- **RBAC**: which zone, name pattern and record type the identity may read or write;
- **per-RRset ownership**: each RRset belongs to a team, and only that team can change or delete it. RRsets
  created outside the gate are *foreign* until a gate administrator adopts them for a team;
- **safe writes**: zone lock, content-hash preconditions (`If-Match`), blast-radius limits;
- a full **audit trail** of who changed what, browsable in the gate UI.

The provider is provider-neutral: the same `dnsgate_record_set` resource manages an RRset in a EuroDNS
zone or in a Route53 hosted zone, alias records included. On zones whose DNS provider has URL forwards
(EuroDNS), `dnsgate_url_forward` manages the HTTP redirect of a name with the same ownership and audit. For
EuroDNS only, the [kamorionlabs/eurodns](https://registry.terraform.io/providers/kamorionlabs/eurodns)
provider also works through the gate.

## Example

```terraform
# The provider talks to a dns-gate, which holds the DNS provider credentials
# (EuroDNS, Route53...) and enforces RBAC and per-RRset ownership. Terraform
# only proves its identity, here with a JWT signed by AWS STS for the current
# IAM role (IAM outbound identity federation).
terraform {
  required_providers {
    dnsgate = {
      source = "KamorionLabs/dnsgate"
    }
  }
}

provider "dnsgate" {
  endpoint = "https://dns-gate.example.com" # or DNSGATE_ENDPOINT

  auth {
    aws_web_identity {
      audience = "dns-gate"
    }
  }
}

# Other methods, exactly one per provider (plus optionally one CI method):
#   auth { token_file    = "/var/run/secrets/tokens/dns-gate" }
#   auth { token_command = ["my-oidc-helper", "--audience", "dns-gate"] }
#   auth { token         = var.gate_token }
# Without an auth block, DNSGATE_TOKEN or DNSGATE_TOKEN_FILE is used.
```

Other authentication methods are described in the [authentication guide](guides/authentication). To move
existing `aws_route53_record` resources under the gate without touching DNS, see
[Migrating from aws_route53_record](guides/migrating-from-route53).

## Concurrency and retries

Every write is a single RRset change with a precondition: creation sends `If-None-Match: *`, updates and
deletions send `If-Match` with the content hash read at the last refresh, so a change made since then
(another run, the UI) is reported instead of being overwritten. Requests answered `423 zone_locked` (another
write holds the zone), `429`, `5xx` or lost in transit are retried with exponential backoff, honouring
`Retry-After` (`max_retries`, default 10). When a write is refused after a retry because an earlier attempt
was applied, the provider reads the RRset back and accepts the result if it holds the desired content.

The client is safe for Terraform's default parallelism; the gate serializes writes per zone.

### Optional

- `auth` (Block, Optional) How to obtain the bearer token sent to the gate: exactly one method, plus optionally one CI method (`azure_devops`, `github_actions`) that takes precedence inside its CI system. Without this block, `DNSGATE_TOKEN` or `DNSGATE_TOKEN_FILE` is used. See the authentication guide. (see [below for nested schema](#nestedblock--auth))
- `endpoint` (String) Base URL of the gate, for example `https://dns-gate.example.com`. Env: `DNSGATE_ENDPOINT`.
- `max_retries` (Number) Retries of a request answered 423 `zone_locked`, 429, 5xx or lost in transit, with exponential backoff (1s doubling, at most 30s, `Retry-After` honoured). Default 10. `0` disables retries.
- `request_timeout` (String) Timeout of one request, as a Go duration. Default `60s`.
